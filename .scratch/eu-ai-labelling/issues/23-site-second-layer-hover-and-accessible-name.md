# 23: Site reference second layer hover gap and button name

**What to build:** Follow-up from 08 (Site integration). Two findings in the reference implementation of `skills/eu-ai-labelling/references/site.md`:

- **Hover gap (likely, not browser-verified).** `.eu-ai-label__details` has `margin-top: 0.25em`, so the gap between the label and the second layer sits outside both boxes. The script closes the layer on `mouseleave` of `.eu-ai-label` when it is not pinned. Moving the pointer from the button toward the details fires `mouseleave` and hides the layer before it can be reached. The layer is then not hoverable, which WCAG 1.4.13 requires and which the file itself cites. Keyboard and click paths are unaffected. Fix: remove the margin gap, or use `padding-top` on the details so the gap stays inside its box. Alternatively, delay the `mouseleave` close slightly. Verify in a real browser once one is available; none is installed in the current environment.
- **Redundant accessible name.** The button's accessible name is the icon `alt="AI"` plus the visible text, so it reads as "AI Generated with AI" (or "IA Generato con IA"). The reference does not say whether `iconAlt` should be empty when the text label already carries the meaning. Fix: note in `site.md` that `iconAlt` is deliberately the icon name, or set `alt=""` when the text label fully names the content.
