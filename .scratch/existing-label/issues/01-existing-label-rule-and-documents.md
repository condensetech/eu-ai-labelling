**What to build:** The shared Existing Label rule in `SKILL.md`, applied first to Markdown and HTML documents (`references/text.md`). This is the tracer bullet the other content types follow. See [spec](../spec.md).

**Blocked by:** none

**Status:** resolved

- [x] `SKILL.md` states the rule once: what an Existing Label is (visible, not applied by this plugin; not Marking, not alt text alone), stop before changing any file, report where it is, what it says and whether its wording matches `generated`/`modified`, give no adequacy verdict, and ask whether to add the EU Icon anyway. Each reference says where its check happens.
- [x] Don't ask when the request already deals with the Existing Label. The report still names it.
- [x] Labelling anyway adds the EU Icon in its usual place and never edits or removes the Existing Label. Removing or replacing it happens only on explicit request, as a plain edit.
- [x] Never claim no Existing Label was found.
- [x] `references/text.md`: check the document's text for a disclaimer, another AI icon or a "generated by" footer, next to the existing check for the plugin's own marker. A marker of this plugin stays handled as today.
- [x] **Whether a Label is required:** when the content visibly has an Existing Label, the answer says so as a fact, alongside the official sources, with no legal verdict.
- [x] Doc tests for `SKILL.md` and `text.md`. Eval scenarios: a Markdown post with a disclaimer (asks before labelling), and a request that already says "label anyway" (labels without asking, names the Existing Label in the report).
