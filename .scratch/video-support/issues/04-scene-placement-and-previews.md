# 04: Choose a fixed position using scenes and previews

**What to build:** A user can assess the Label across changing scenes, correct its fixed position and approve the complete video with a clear understanding of what the previews do and do not establish.

**Blocked by:** 03 - Choose continuous or periodic Label visibility.

**Status:** resolved

- [x] Produce representative source frames from different parts of the video and short labelled excerpts using the selected rendering settings. For periodic display, include relevant visible windows and their transitions rather than sampling only times when the Label is absent.
- [x] Use the samples, existing corner preferences and agent visual inspection to propose one fixed position that avoids obvious interference with faces, text, subtitles and the principal subject. Ask the user when the samples offer no suitable corner; do not move the Label automatically during playback.
- [x] Keep the contrast backing plate and chosen appearance stable. Honour user adjustments to position and size while retaining the existing minimum-size and fit checks.
- [x] Make excerpts representative of the eventual Labelled Copy: same Icon Variant, geometry, colour treatment and visibility settings. Report failed sample extraction or unavailable inspection rather than pretending a preview was checked.
- [x] State that sampling cannot guarantee an unobstructed Label placement in every frame. Provide the full Labelled Copy for final approval; an explicit preview waiver may skip visual review but never bypass output-integrity checks.
- [x] Rerender and renew approval when the user changes placement or visibility. Preserve the original and any previous valid Labelled Copy if preview generation or rendering fails.

## Comments

New subcommand `video-preview <video>` takes the same `--variant`, `--corner`, `--colour`, `--size`, `--visibility`, `--window`, `--every` and `--threshold` as `video-apply` (shared through one parser helper), plus `--out <folder>` (default `<video>.label-preview` next to the video; refused with `usage` when it is the video, a Labelled Copy or a file) and `--frames <n>` (default 5). It writes `frame-NN-<t>s.png` source frames spread over the video and labelled `excerpt-NN-<start>-<end>s.<ext>` excerpts, and replaces only files of exactly those names from an earlier preview. The result carries the same settings fields as `video-apply` (`variant`, `corner`, `colour`, `plate_box`, `icon`, `margin`, `visibility`), `frames` (`time`, `path`, `status`), `excerpts` (`start`, `end`, `label_visible`, `path`, `status`, `decoded_frames`), `complete`, `failed`, `excerpt_note` and `sampling_note` (samples cannot show the Label is clear in every frame). A failed frame or excerpt is a `failed` entry with `error` and no `path`; when nothing at all could be made the command fails with the new code `preview_failed`. The checks before rendering (`label_plan`) and the Label itself (`draw_label`: colour, overlay, even-snapped position) are shared with `video-apply`, and excerpts go through `render_command(..., excerpt=(start, seconds))`, which only adds `-ss`/`-t` before the input and `-an -sn -dn`: the same filter graph, counter-rotation, encoder and `-copyts` timestamps, so the periodic `enable` expression is unchanged. Excerpts: continuous display at the start, middle and end (3 s each, merged when they overlap); periodic display around the first, second and last windows with 1 s of hidden time either side, split into an onset and an offset excerpt when a window is longer than 4 s.

Decisions: excerpts carry video only (copied audio would not be cut cleanly at the seek point); the tool does no face or text detection, so references/video.md step 4 has the agent open every frame, call a corner free only when it is clear in every frame, and ask the user when none is; the Label never moves. Steps were reordered: 3 is now the visibility choice and 4 the preview (the old step 3 "Choose the corner" is folded into it), so the preview uses the settings `video-apply` will. Approval (step 6) now states what the previews did and didn't establish, and a corner or size change goes back to step 4. SKILL.md's pointer to the references step was stale (step 7, now 8) and is fixed. Tests (tests/unit/test_video_preview.py, real ffmpeg) cover a three-scene video whose competing corner changes (`corner_scenes` fixture), excerpts identical to the Labelled Copy's Label box and pixels, rotated videos (90 and 180), periodic short and long windows with an offset start and audio, the out folder and the minimum-size and fit checks, simulated frame and excerpt failures, a preview that makes nothing, and an unsupported video. Left out: the unsuitable-corner and user-correction cases are agent behaviour, covered by the docs tests only, and no video workflow eval exists yet (deferred since ticket 02).
