# 09: Label video batches with independent outcomes

**What to build:** A user can request Labels for several local videos, answer shared questions once, review the results together and retry selected files without a failure discarding successful work.

**Blocked by:** 04 - Choose a fixed position using scenes and previews.

**Status:** resolved

- [x] Discover videos from an explicitly supplied list, glob or folder using the existing batch scope. For a folder, inspect its direct files; exclude existing Labelled Copies and report them as skipped.
- [x] Reuse answers already supplied for the batch. Group unresolved Icon Variant, visibility and placement questions into one message, distinguish shared answers from per-file exceptions and avoid asking again about resolved files.
- [x] Keep placement specific to each video and apply the agreed short/long-video defaults per file when no explicit shared preference overrides them. Creative Work videos retain an incorporated Label.
- [x] Process each file through its available validated rendering path. Do not hard-code a separate batch support matrix or require completion of every format/HDR extension before a baseline batch can work.
- [x] Isolate inspection, capability, rendering, validation and preview failures. Continue independent eligible files, report pending decisions separately, preserve originals and previous valid copies, and clean partial outputs.
- [x] Present one combined review that identifies each Labelled Copy, its effective settings, preview coverage and any failure/refusal/skip. Honour existing approval or explicit preview-waiver rules and rerender only the files the user requests.
- [x] Expose per-file approval outcomes for later project-reference handling without routing unapproved or failed files through image-specific updates. Actual video-reference updates remain the responsibility of the separate reference ticket.
- [x] Demonstrate a batch containing different durations, a shared answer, a per-file exception, an existing Labelled Copy and a failing file. Verify partial success, grouped questions, selective retry and renewed approval of changed copies. Exercise additional format/HDR handlers when they are present without making them blocking edges.
- [x] Update batch instructions and workflow evaluations, preserving established image-batch behaviour.

## Comments

Discovery reuses `score`'s batch form (`score_batch`). A folder is now scanned for `IMAGE_SUFFIXES | VIDEO_SUFFIXES` (direct, visible files only, through `folder_media`, which replaces `folder_images`). A listed or found video goes to a new `videos` list (`{path, media: "video"}`), unscored; `images`, per-file `refused` and `skipped` entries carry `media` too, and a video's Labelled Copy is skipped like an image's. `no_images` now fires only for a folder holding neither (message "No image or video found"; code kept). The listing never decides support: each video goes through its own `video-inspect`/`video-apply`, so there is no batch support matrix and format/HDR handlers apply as they land. A single-path `score` on a video is unchanged (the image refusal).
